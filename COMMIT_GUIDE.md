# Как сделать коммиты и опубликовать проект

Коммит — сохраненное состояние выбранных файлов проекта в истории Git.
Команда `git add` выбирает файлы, `git commit` сохраняет их локально,
а `git push` отправляет историю на GitHub.

## Подготовка

Установите Git. Откройте терминал в распакованной папке `rain_animation`.
Создайте и активируйте venv по README. Если в папке уже есть история Git,
сначала изучите `git log --oneline`: инструкция ниже рассчитана на новый проект.
Не удаляйте существующую историю ради повторения этих шагов.

```bash
git init
git branch -M main
git config user.name "Садритдинов Эльдар Сайфиддинович"
```

Укажите свой адрес, связанный с GitHub (подставьте реальный адрес вместо примера):

```bash
git config user.email "YOUR_GITHUB_EMAIL"
```

Настройки действуют только для этого репозитория. Не оставляйте пример вместо почты.

## Четыре коммита

### 1. Только README, сообщение — полное ФИО

```bash
git add README.md
git diff --cached --name-only
git commit -m "Садритдинов Эльдар Сайфиддинович"
```

Перед коммитом в выводе должен быть только `README.md`.
Не используйте `git add .` на этом шаге.

### 2. Модель и структура

```bash
git add .gitignore requirements.txt src/__init__.py src/model.py
git commit -m "Add rain model and project structure"
```

### 3. Окно и анимация

```bash
git add main.py src/app.py src/renderer.py
git commit -m "Add animated rain window and controls"
```

### 4. Тесты, инструкция и окружение

```bash
git add tests COMMIT_GUIDE.md venv
git commit -m "Add model tests, commit guide and virtual environment"
git status
git log --oneline --reverse
```

Папка venv намеренно не исключена из Git: это прямое требование преподавателя.
Она зависит от системы; на другом компьютере ее нужно пересоздать по README.
Не добавляйте сторонние крупные библиотеки в окружение этого проекта.
Четыре коммита здесь разделяют готовые файлы на логические группы;
при самостоятельной разработке сохраняйте изменения по мере работы.

## Публикация на GitHub

1. Войдите в свою учетную запись GitHub.
2. Создайте репозиторий `rain-animation`, выберите Public.
3. Не добавляйте автоматически README, .gitignore или лицензию:
   они создадут отдельную начальную историю.
4. Скопируйте HTTPS-адрес нового репозитория.
5. Выполните команды, заменив YOUR_USERNAME своим логином:

```bash
git remote add origin https://github.com/YOUR_USERNAME/rain-animation.git
git push -u origin main
```

При запросе авторизации используйте предложенный GitHub вход через браузер
или токен доступа; пароль от учетной записи для Git не подходит.
Если origin уже настроен, сначала посмотрите `git remote -v` и убедитесь,
что адрес ваш, вместо повторного `remote add`.

Откройте репозиторий в браузере: проверьте файлы, публичность и четыре коммита.
В первом коммите должен быть только README, а сообщение — ваше полное ФИО.
Добавьте ссылку в учебную Google-таблицу «Репозитории».

## Следующие изменения

```bash
git status
git add ИМЯ_ИЗМЕНЕННОГО_ФАЙЛА
git diff --cached
git commit -m "Update rain controls"
git push
```

В `git add` подставляйте настоящее имя файла. В сообщении кратко описывайте
действие с заглавной буквы: Add, Fix, Update, Remove.
